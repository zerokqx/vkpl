# Протокол VK Music

Дата исследования: 2026-10-07.

## Источники и статус

Первоначальная реализация основана на исследовании исходников [VKWebClient](https://github.com/ilyhalight/vk-audio/blob/master/src/client.ts), [обёрток методов](https://github.com/ilyhalight/vk-audio/blob/master/src/index.ts) и [модели веб-токена](https://github.com/ilyhalight/vk-audio/blob/master/src/types/client.ts) проекта `@toil/vk-audio`. Затем протокол проверен через Chrome DevTools MCP 1.10.1 на авторизованной вкладке `vk.ru/music`, и непосредственно Rust-клиентом.

Исходный MCP запускал отдельный headless Chromium. Подключение к браузеру пользователя выполнено через CLI того же Chrome DevTools MCP с `--autoConnect --userDataDir ~/.config/chromium`, после включения `chrome://inspect/#remote-debugging` и подтверждения пользователем. Режим Chromium 149 использует адрес из `DevToolsActivePort`; запрос `/json/version` на порту 9222 возвращал 404. Этот сценарий поддержан командой `vkpl login existing` и проверен живым входом.

В Network исследованы получение веб-токена, переход в «Моя музыка», поиск, загрузка раздела и запросы веб-плеера. В Runtime прочитаны функции `fetchAudioUrls`, `fetchAudios`, `_ensureHasURL` плеера. Секретные значения не включены в этот документ.

## Обмен

1. Cookies VK импортируются с сохранением доменов и путей. Принимаются только `vk.ru`, `vk.com` и их поддомены; cookie другого домена не переносится на VK.
2. `POST https://login.vk.ru/?act=web_token`: форма `version=1`, `app_id=6287487`, заголовки Origin/Referer VK, cookie jar.
3. Ожидается `data.access_token`, `data.expires` (UNIX timestamp), `data.user_id`.
4. `POST https://web.api.vk.ru/method/{method}`: форма `v=5.289`, `client_id=6287487`, `lang=ru`, `access_token` и параметры метода. Сайт помещает `v` и `client_id` в query string; передача через форму SDK тоже проверена.
5. Ответ: `{ "response": ... }` или `{ "error": { "error_code": ... } }`.

Версия и app ID сверены с Network и доступны в `ClientBuilder`. Встроенных client secret нет. Автоматическое обновление сериализуется: несколько одновременных запросов используют один новый токен. При коде 5 операция чтения обновляет токен и повторяется один раз; код 6 / HTTP 429 получает не более двух повторов. CAPTCHA не повторяется.

## Методы SDK

| Метод VK | Параметры | Результат SDK |
| --- | --- | --- |
| `users.get` | текущая сессия | `User` |
| `audio.search` | `q`, `offset`, `count` | `Page<Track>` |
| `audio.get` | `owner_id`, `offset`, `count`, опционально `album_id`, `access_key` | `Page<Track>` |
| `audio.getPlaylists` | `owner_id`, `offset`, `count` | `Page<Playlist>` |
| `audio.getById` | `audios=owner_id_id[_access_key]` | свежий `Track` с URL |
| `catalog.getAudio` | `need_blocks=1` | `Catalog` |
| `catalog.getAudioSearch` | `query`, `need_blocks=1` | `Catalog` |
| `catalog.getSection` | `section_id`, опционально `start_from` | `SectionPage` |
| `audio.getLyrics` | `lyrics_id` | текст |
| `audio.searchArtists` | `q`, `offset`, `count` | `Page<Artist>` |
| `catalog.getAudioArtist` | `artist_id`, `need_blocks=1` | `Catalog` с профилем, треками и релизами |
| `catalog.getBlockItems` | `block_id`, `count`, опционально `start_from` | `BlockPage` с курсором `block.next_from` |
| `audio.getStreamMixAudios` | `mix_id` | новая порция `Vec<Track>` |

Непосредственно перед воспроизведением SDK обновляет URL через `audio.getById`. MPV воспроизводит полученный HLS/MP3 как есть. Замены `index.m3u8` на `.mp3` нет. Наличие записи в списке не означает доступности полного аудио для сессии.

## Наблюдения на настоящем API

- `web_token`: подтверждены `version=1`, `app_id=6287487` и схема `type/data`.
- Библиотека сайта использует `al_audio.php`, `act=section`, `section=all`, `owner_id`, `claim`, `is_layer`, `al=1`. Ответ содержит `payload=[0,[html,section]]`; у `section.playlist` есть `list`, `totalCount`, `nextOffset`, `hasMore`. Треки представлены позиционными массивами.
- Поиск сайта использует `catalog.getAudioSearch`, `query`, `need_blocks=1`, `screen_ref`. Ответ содержит каталог, аудио, плейлисты и дополнительные сущности. SDK моделирует музыкальную часть, игнорируя неизвестные поля.
- Веб-плеер обращается к `al_audio.php?act=reload_audio` с `ids`, а при `bad_hash` использует `reload_audios` с `audio_ids`, затем обновляет URL. В SDK выбран типизированный `audio.getById`: работоспособность для доступных записей проверена.
- В `audio.get` при запрошенных 100 элементах наблюдалось 99 возвращённых записей. SDK хранит следующее смещение по размеру запрошенного окна, чтобы не повторять записи; `TrackPager` использует это смещение автоматически.
- Часть старых записей возвращает `content_restricted=2` и пустой URL. TUI показывает `×`, не добавляет их в создаваемую очередь и объясняет ограничение при попытке запуска. Их воспроизведение не заявляется.

Проверены Rust-методы `me`, `library`, `search`, `playlists`, `catalog`, `section`, `playlist_tracks`, `resolve`; медиаресурс доступного трека вернул HTTP 200. Проверен вход из существующего Chromium. В настоящем TUI проверены поиск, воспроизведение двух треков, пауза, перемотка, громкость, смена трека и сохранение очереди; MPV декодировал аудио через `--ao=null`, без вывода на колонки. Проверка не означает, что вся музыка доступна всем аккаунтам.

## Границы текущей реализации

- OAuth-токен произвольного приложения может не иметь музыкальных прав. Основной способ входа — веб-сессия.
- SMS/QR/пароль и дополнительные проверки выполняются в настоящем VK ID внутри браузера.
- SDK предоставляет разделы каталога и курсоры. Экран «Для вас» показывает аудиозаписи первого ответа каталога или его раздела по умолчанию; для непрерывного персонального потока используется отдельный раздел «Миксы».
- Текст песни запрашивается только при наличии `lyrics_id`; синхронное караоке не реализовано.
- Отрисовка TUI и IPC плеера предназначены для Unix. MPRIS работает через пользовательский D-Bus; Windows пока не реализована.
- Живой вход через отдельное окно с QR/SMS/паролем, повторное подтверждение 2FA, тексты песен и ограничения других аккаунтов отдельно не проверялись. Браузерный сценарий передаёт эти способы самому VK ID.
- Автотесты подтверждают поведение клиента на контролируемых ответах; доступность приватного API зависит от текущего VK и сессии.

Не сохраняйте в репозитории HAR, Cookie/Authorization, токены или подписанные URL. Для воспроизводимых фикстур используйте искусственные идентификаторы и значения.

## Дополнение: исполнители и миксы

Исследованы загруженные скрипты авторизованной вкладки VK через Chrome DevTools MCP (`evaluate_script`): API-обёртка содержит `audio.searchArtists`, `audio.getStreamMixAudios`, `audio.getStreamMixSettings`; реализация очереди микса вызывает `getStreamMixAudios({mix_id, entity_id?, options?, ref?})` при подгрузке. Ответ — массив аудио. Отдельного `audio.getStreamMix` нет (API вернул код 3).

Непосредственные запросы с существующей веб-сессией подтвердили:

- `audio.searchArtists(q=Кино)` возвращает `count/items`, где `id` — строка, `name` — имя, `domain` — адрес страницы исполнителя.
- `catalog.getAudioArtist` принимает ID из результата поиска; также сработал domain. В исследованном ответе было 30 треков и 17 плейлистов разных полок. TUI отделяет полку «Релизы» по `playlists_ids`, чтобы не смешивать собственные релизы с чужими подборками.
- `catalog.getBlockItems` с ID музыкального блока и `start_from=next_from` вернул следующие 100 треков. Курсор непрозрачный: клиент передаёт его без изменений.
- `catalog.getAudio` содержит `audio_stream_mixes` с `stream_mix.id=common` и полку «Собрано алгоритмами» с `playlists_ids`. Один из таких плейлистов прочитан через `audio.get`: 100 треков.
- `audio.getStreamMixAudios(mix_id=common)` вернул массив из трёх треков. Размер порции задаёт VK. SDK не повторяет запрос автоматически при сетевом/API сбое, потому что сервер может продвинуть поток. Следующая попытка выполняется явно.

Только схемы и количество записей использованы в документации; токены, cookies, подписанные медиассылки и персональные ответы не добавлены в проект. Эти наблюдения подтверждают протокол, а не поведение всех новых экранов TUI.

## MPRIS

Адаптер реализует интерфейсы `org.mpris.MediaPlayer2` и `org.mpris.MediaPlayer2.Player` по [спецификации MPRIS](https://specifications.freedesktop.org/mpris/latest/Player_Interface.html). D-Bus команды поступают в основной цикл приложения, состояние публикуется отдельной задачей; подписанные URL в Metadata не передаются. Position и Seek используют микросекунды, Volume — диапазон 0…1. SetPosition проверяет ID текущего трека. Отсутствие D-Bus не мешает запуску TUI.

## Дополнение: полная выдача треков исполнителя и буферизация

Для «лиззз» `catalog.getAudioArtist` отдал один трек в блоке «Популярное» без `next_from`, а `audio.search(q=лиззз)` отдавал более 80 результатов. Большинство найденных треков не имело `main_artists`. Поэтому `artist_tracks` ищет по имени и фильтрует результаты по ID основного исполнителя, когда он есть, или по полю `artist` с учётом совместных записей. Страница исполнителя сначала показывает каталог, затем добавляет результаты этого поиска. Полка релизов использует «Релизы», а если её нет — музыкальную полку участия в релизах.

Подписанные URL VK ведут на HLS `index.m3u8`; исследованная медиаплейлиста содержала AES-ключи и сегменты `.ts`. Прямая склейка сегментов не подходит. Предзагрузка поэтому использует FFmpeg `-c:a copy -f matroska` и приватный временный каталог; на одном доступном треке VK выгрузка завершилась с кодом 0 и дала непустой `.mka` файл. Одновременно готовятся до трёх следующих треков, текущий имеет приоритет. Готовые файлы используются только в живой сессии и удаляются из временного каталога после воспроизведения или выхода. При ошибке FFmpeg остаётся раннее обновление ссылки и обычная загрузка MPV.
